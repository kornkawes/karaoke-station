# เทียบฟังก์ชันกับแอป KaraokeStation เดิม

อัปเดต 2026-09-08 · ขอบเขต: HTML design preview · Cara ตรวจอิสระ PASS 34/34 (ดู qa/QA-REVIEW.md)

Nut ยืนยันว่า “แบบเก่า” หมายถึงแอปเดิม ไม่ใช่ HTML ร่างแรก ดังนั้นใช้ `src/HostedApp.jsx` ซึ่งเป็นหน้าหลักตาม `src/main.jsx` และพฤติกรรมคิวใน `server/lib/library.js` เป็นฐานเทียบ

## ข้อผิดพลาดในพรีวิวรอบก่อน

มีการเอา transport ออกจาก Host แต่ไม่ได้ย้ายปุ่มที่ใช้งานได้ไป Mobile ให้ครบ และบางปุ่มเปลี่ยนเพียงข้อความโดยไม่เปลี่ยน state เช่น โหมดผลัดกันร้อง ส่วน “เล่นต่อไป” มีพฤติกรรมคนละอย่างกับ “เล่นทันที” ของแอปเดิม การลดข้อมูลบน Host ไม่ควรลดความสามารถของระบบ

## ฟังก์ชันที่เติมในพรีวิว

| ฟังก์ชัน | พฤติกรรมใน HTML รอบแก้ |
|---|---|
| ใส่ชื่อเข้าห้อง | มีหน้ากรอกชื่อก่อนเข้า controller; เป็น session จำลอง |
| ค้นหา / เพลงโปรด | ค้นในชุดเพลงตัวอย่าง บันทึกและกรองเพลงโปรดได้ |
| เพิ่มเพลง | เพิ่มคิวได้สูงสุด 100 เพลงตามขีดจำกัดเดิม; ถ้าไม่มีเพลงปัจจุบันจะเริ่มเพลงแรกทันที |
| เล่นทันที | เปลี่ยนเพลงปัจจุบัน เอารายการที่เลือกออกจากคิว บันทึกเพลงก่อนหน้าเป็น “หยุดก่อนจบ” |
| ข้ามเพลง | เปลี่ยนเป็นเพลงถัดไปและบันทึก “ข้ามแล้ว”; ข้ามเพลงสุดท้ายได้และกลับไปรอเพลงแรก |
| ผลัดกันร้อง | จัดคิวตามผู้ขอเป็นรอบเมื่อเปิดโหมดหรือเพิ่มเพลง เริ่มจากผู้ขอถัดจากคนที่กำลังร้อง |
| ย้าย / ลบคิว | ทำงานกับรายการจริงใน state จำลอง ย้ายด้วยลูกศรได้แม้เปิดผลัดกันร้อง |
| ประวัติ / ร้องอีก | ประวัติเปลี่ยนตามการเล่นทันที ข้าม และจบเพลง; เพิ่มเพลงจากประวัติกลับเข้าคิวได้ |
| เล่น / พัก / เสียง / mute | ย้ายมาอยู่ในแผง remote บน Mobile เปลี่ยน state ได้; ไม่มีเสียงจริงเพราะยังเป็นภาพนิ่ง |
| สร้างห้องใหม่ | อยู่ในการตั้งค่าบน Mobile ตามแนวทางมือถือเป็นรีโมท เปลี่ยนรหัสห้องจำลองและล้าง current/queue/history หลังยืนยัน เก็บเพลงโปรดไว้ |
| เชิญเข้าห้อง | มีแผงคำเชิญและปุ่มคัดลอกข้อความตัวอย่างตามการกดของผู้ใช้ ไม่ส่งข้อความให้ผู้อื่น |
| Host | คงภาพเต็มจอ ข้อมูลห้อง/QR ตัวอย่าง เพลงถัดไป และ fullscreen; เพลงถัดไปอัปเดตตาม state จาก Mobile |
| ซิงก์หน้าพรีวิว | ใช้ข้อมูลร่วมกันระหว่างแท็บใน browser เดียว ผ่าน localStorage/BroadcastChannel; ทดสอบ file:// บน Chrome แล้ว |

“จบเพลงตัวอย่าง” ใช้จำลองเหตุการณ์วิดีโอเล่นจบ เพื่อดูประวัติและการเลื่อนเพลง ในแอปจริงเหตุการณ์นี้มาจาก YouTube Player ไม่ใช่ปุ่มที่จำเป็นสำหรับผู้ใช้

## ส่วนที่ยังต้องเชื่อมแอปจริง

- วิดีโอ YouTube, การค้นเพลงออนไลน์, วาง URL/Video ID เพื่อดึง metadata และภาพปกจริง
- QR / join token / room session จริง และการส่งลิงก์เข้าห้องผ่าน Web Share หรือ LINE
- การซิงก์ข้ามมือถือและทีวีผ่าน server/socket พร้อมสิทธิ์ผู้ใช้, session หมดอายุ และการป้องกันคิวชนกัน
- สถานะ autoplay blocked, video error/private/embedded-disabled, reconnect และ search unavailable ที่เกิดจากบริการจริง

HTML นี้ยังไม่เทียบเท่าแอปที่เชื่อมระบบครบ จึงไม่ใช้แทนระบบจริง และไม่ได้แก้หรือลบฟังก์ชันใน `src/` หรือ `server/` เดิม

## ความแตกต่างของ lane เดิม

HostedApp ปกติมี Skip บน Mobile แต่ไม่มี host transport เต็มชุด การเล่น/พักและปรับเสียงใน remote นี้เป็นการรองรับความสามารถจาก local lane/ร่างเดิม โดยการเชื่อม Hosted backend ภายหลังต้องตรวจสิทธิ์และ API อีกครั้ง

ฟังก์ชันเนื้อร้อง (lyrics drawer / LRCLIB), ชื่อสถานี, API-key settings และการหมุน invite/session มีอยู่ใน local lane หรือ Modern UI บางส่วน ไม่ใช่ HostedApp ปกติ จึงยังไม่ใส่ API key หรือระบบเนื้อร้องปลอมใน HTML นี้ ต้องรักษาไว้ตาม lane ที่เลือกเมื่อย้ายดีไซน์เข้าตัวแอปจริง

## ข้อจำกัดพรีวิว

- ข้อมูลใช้เฉพาะ browser นี้ ไม่ใช่ห้องจริง และไม่ใช่การซิงก์ระหว่างอุปกรณ์
- browser ที่ไม่อนุญาต storage จะใช้ข้อมูลในหน้านั้นระหว่างเปิดอยู่; อย่าถือว่าได้รับการบันทึกถาวร
- การทำงานพร้อมกันหลายผู้ใช้และการแก้คิวชนกันยังต้องใช้กลไกของ server จริง
- ฟังก์ชันเต็มจอยังต้องมี gesture จากผู้ใช้ที่หน้าจอนั้นตามข้อกำหนดของ browser
